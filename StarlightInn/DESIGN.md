# 星灯旅店 · Starlight Inn

## 本轮范围

- 独立 Godot 4 工程，不修改 ForestGlow / HollowBell。
- 先完成 Image 2.5 美术素材，再开始游戏实现。
- 一间中世纪幻想旅店大厅：暖金灯火、孔雀蓝夜色、木石结构与星灯。
- HD-2D 风格：固定镜头、像素人物、纵深层次、地面投影、局部灯火与浮尘。
- 玩家可移动，与不同位置的 NPC 交谈；有分支选项、返回、取消、输入与聊天记录。
- **仅预留能力接口。没有真实 AI/Azure 连接、凭据、网络调用或云资源写操作。**
- 所有能力返回都清楚标记为本地演示数据，不宣称是现实资源状态。

## 素材先行

用 `gpt-image-2.5-flare` 制作大厅、主角四向动作图、NPC 动作图、配套头像、装饰图集和对话面板。
原始生成图片放在 `assets/source/`；可直接使用的切片和透明素材放在 `assets/sprites/` 与 `assets/ui/`。
生图任务、提示词与参数以生图队列为准，不在图片目录另存回执或提示词文件。

## 交互约定

- WASD / 方向键移动，E / Enter 交谈，Esc 关闭当前层，鼠标选择对话。
- 鼠标点击地面可走近；点击 NPC 可走近并开始聊天。
- 对话时暂停人物行走；输入框聚焦时按键不得穿透成移动。
- 显示邻近 NPC 提示、能力类型、访问记录和本地演示状态。
- 关机只预览：先选择示例目标，再确认，结果必须明确“未执行任何真实操作”。
- 对话关闭或切换时，过期请求不得把结果写进另一个 NPC 的会话。

## 能力扩展约定

统一请求包含 `request_id`、`npc_id`、`capability`、`action`、`arguments`；统一响应包含 `ok`、`mode`、`message`、`data`、`error`。
游戏 UI 只依赖接口与信号；默认实现是本地演示适配器。未来可替换适配器连接受保护的后端，凭据不进入客户端。
真实写操作不在本轮实现范围；预览不是授权，也不能在日后接入时直接当作云端执行凭据。

## 完成判定

1. 所有实际使用的生成素材已保存并进入独立项目。
2. 大厅中能四向移动、避开家具、接近四位 NPC 并打开各自会话。
3. 分支选择、自由输入、关闭/重开、关机预览与访问记录能工作。
4. 自动测试通过；Windows 导出可启动，完成真实桌面键鼠验证。
5. 不连接任何真实能力服务，不修改云端资源；交付可直接运行的 EXE。
